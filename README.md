# Patient Management System

A React and Vite frontend for managing patient admissions. The frontend uses the
FastAPI backend at `http://127.0.0.1:8000`.

## Requirements

- Node.js and npm
- Python with the backend dependencies installed
- A database supported by the backend's SQLAlchemy connection string

## Configuration

The backend reads `DATABASE_URL` from the environment or a root-level `.env`
file. Set it to a valid SQLAlchemy database URL before starting the backend.
Keep database credentials out of source control.

The frontend API base URL is currently set in `src/api.js`:

```text
http://127.0.0.1:8000
```

The backend enables CORS for all origins. Restrict allowed origins before
deploying it outside local development.

## Run locally

Start the backend from the repository root, with `DATABASE_URL` configured:

```powershell
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Start the frontend in a second terminal:

```powershell
cd frontend\Patient_managment_system
npm install
npm run dev
```

The frontend provides development and production build checks:

```powershell
npm run lint
npm run build
```

FastAPI's interactive API documentation is available at
`http://127.0.0.1:8000/docs`.

## API reference

All endpoints below use the `http://127.0.0.1:8000` base URL. Paths are
case-sensitive.

### `GET /api/options`

Returns values used to populate the patient form:

```json
{
  "genders": ["Male", "Female", "Other"],
  "ward": ["General", "ICU", "Emergency", "Maternity", "Pediatric"],
  "departments": ["Cardiology", "Neurology", "Orthopedics", "Pediatrics", "General Medicine"],
  "doctors": ["Dr. Sharma", "Dr. Banerjee", "Dr. Iyer", "Dr. Khan", "Dr. Das"]
}
```

The backend response key is `ward` (singular). The frontend adapter exposes
this as `wards` to the React components.

### `GET /api/patients`

Returns patient records ordered by descending ID. All query parameters are
optional and can be combined:

| Parameter | Behavior |
| --- | --- |
| `search` | Case-insensitive partial match against patient name |
| `ward` | Exact ward match |
| `department` | Exact department match |
| `doctor` | Exact doctor match |

Example: `GET /api/patients?search=asha&ward=General`

### `POST /api/patients`

Creates a patient and returns the created record with HTTP `201`. The database
generates the `id`; do not include it in the request body.

```json
{
  "name": "Asha Patel",
  "age": 34,
  "gender": "Female",
  "ward": "General",
  "department": "Cardiology",
  "doctor": "Dr. Sharma",
  "admission_date": "2026-11-25",
  "status": "Admitted"
}
```

`status` is optional and defaults to `Admitted`. Accepted status values are
`Admitted` and `Discharged`. The age must be between 0 and 120, names may
contain letters and spaces, and admission dates cannot be in the future.
Dates use `YYYY-MM-DD`.

### `PUT /api/patients/{pid}`

Replaces the patient's editable fields and returns the updated record. Send the
same fields as for `POST` (including `status` when changing admission status).
The patient ID is supplied in the URL, not required in the body.

Example: `PUT /api/patients/12`

### `DELETE /api/Patients/{pid}`

Deletes a patient and returns HTTP `204` with no response body. The `Patients`
segment is capitalized in the current backend route; use this exact casing.

### Discharging a patient

There is no dedicated discharge endpoint. The frontend loads the patient and
uses `PUT /api/patients/{pid}` with `status` set to `Discharged`.

## Patient fields

| Field | Type | Accepted values / notes |
| --- | --- | --- |
| `id` | integer | Generated by the database and included in patient responses |
| `name` | string | Required; letters and spaces only |
| `age` | integer | Required; 0–120 |
| `gender` | string | `Male`, `Female`, or `Other` |
| `ward` | string | `General`, `ICU`, `Emergency`, `Maternity`, or `Pediatric` |
| `department` | string | `Cardiology`, `Neurology`, `Orthopedics`, `pediatrics`, or `General Medicine` |
| `doctor` | string | `Dr. Sharma`, `Dr. Banerjee`, `Dr. Iyer`, `Dr. Khan`, or `Dr. Das` |
| `admission_date` | string | Required date in `YYYY-MM-DD` format; cannot be in the future |
| `status` | string | `Admitted` or `Discharged`; defaults to `Admitted` on create |

The department value `pediatrics` is lowercase in the backend schema. The
frontend translates the displayed `Pediatrics` option to and from that value.

## Error responses

Validation errors return HTTP `422` with field-specific messages:

```json
{
  "detail": "Validation failed",
  "errors": {
    "age": "Must be a valid number"
  }
}
```

Updating or deleting a patient that does not exist returns HTTP `404`.
